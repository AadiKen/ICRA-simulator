Current implementation snapshot
The simulator core has been refactored since this document was first drafted.
Current code status:
* schema.js contains the headless simulation core.
* simState is the single runtime state container and stores mutable simulation truth only.
* simulator owns the behavior models: boatModel, goalModel, controlModel, sensorModel, skipperModel, envModel, metricModel, and logger.
* logs are owned by simulator/logger and exposed as sim.logs. They are not stored in simState.
* createInitialSimState builds pure runtime state from scenarioConfig.
* simulator.step(), simulator.runSteps(n), and simulator.runUntilDone(maxSteps) provide the core stepping API.
* waterFieldModel exposes a 3D field-style sampleAt(pos, time) API while remaining internally implemented as a 2D surface height-field.
* boat physics includes hull water samples, buoyancy, relative water drag, torque, angular damping, translational damping, collision failure, and out-of-bounds failure.
* GPS and IMU are implemented as state-based sensors. Lidar, day camera, night camera, and EXO2 intentionally return placeholders until the Three.js/sensor layer exists.
* simulatorSmokeTest.js provides the current smoke test for the headless simulator.

4. Boat Dynamics Layer
Purpose
Advances boat motion using a simplified dynamic model.
Inputs
current boat state
local target from controller

Outputs
updated boat state
Model requirements
capability-limited motion
no spline-following truth
current-driven drift
heading correction under turn-rate limits
acceleration/deceleration limits
Recommended structure
interface BoatDynamicsModel {
 update(
   state: BoatState,
   control: LowLevelGuidanceCommand,
   env: LocalEnvironmentSample,
   dt: number,
   rng: RNG
 ): BoatState;
}
Low-level guidance command

type LowLevelGuidanceCommand = {

};
Update sequence

compute heading error to target
clamp turn response by maxTurnRate
compute desired forward speed
clamp acceleration/deceleration
update velocity in heading direction
add current drift vector
apply wave/disturbance perturbation
update position
recompute derived acceleration/power draw
Build tasks

Implement current drift application

5. Water / Disturbance Field Layer
Purpose
Single shared source for:
boat motion disturbances
wave visuals
Deliverables
WaterField.sampleAt(pos, time)
WaterField.normalAt(x, z, time)
authored region support
procedural perturbation support
Core API
type WaterSample = {
 pos: Vec3;
 surfaceHeight: number;
 velocity: Vec3;
 acceleration: Vec3;
 normal: Vec3;
 depth: number;
 submerged: boolean;
};

interface WaterField {
 sampleAt(pos: Vec3, time: number): WaterSample;
 heightAt(x: number, z: number, time: number): number;
 velocityAt(x: number, z: number, time: number): Vec3;
 accelerationAt(x: number, z: number, time: number): Vec3;
 normalAt(x: number, z: number, time: number): Vec3;
}
Recommended model
Hybrid:
surface height-field with a 3D sample interface
Gerstner-like waves
optional future depth attenuation for wave velocity
Motion consumers
velocity → relative water drag
surfaceHeight/depth/normal → buoyancy
per-hull-point forces → roll/pitch/yaw torque
Render consumers
surfaceHeight → mesh displacement
normal → water shading and boat interaction debug views
velocity/current → flow visualization
Build tasks
Implement constant field
Implement zoned field
Add interpolation between zones
Add optional low-cost noise overlay
Connect same field to both dynamics and rendering

EXO2

21. Tickwise Flowchart
1. Read current SimulationState
2. Sample local environment
3. Determine which sensors are due
4. Sample active due sensors
5. Process sensor latency queues
6. If controller update is due:
      send observations to controller
      receive path + active sensors
7. Translate controller output into low-level guidance
8. Advance boat dynamics by dt
9. Update mission progress
10. Update metrics/cost
11. Append logs
12. Push updated state to renderer/UI
13. Repeat

22. Ownership Layout
A. Scenario Schema Layer
Runs:
once at scenario submission
optionally again on reset/load/import
Owns:
config validation
normalization
defaults
compatibility/versioning
Does not own:
live runtime state
rendering
simulation stepping

B. Runtime State Layer
Runs:
once at initialization
then continuously read/write during simulation
Owns:
all authoritative live state
Does not own:
visualization logic
UI logic
controller transport details

C. Simulation Clock / Scheduler Layer
Runs:
continuously while simulation is active
Owns:
fixed tick cadence
controller cadence
sensor due checks
Does not own:
boat physics

D. Environment + Water Field Layer
Runs:
every tick, sampled as needed
Owns:
local environment query

Does not own:
how boat responds physically
how water is rendered

E. Sensor Scheduling Layer
Runs:
every tick
Owns:

Does not own:

23. Pseudocode
function startSimulation(userConfig: ScenarioConfigInput) {
  const scenario = validateAndNormalizeScenario(userConfig);

  const sim = new simulator(scenario);
  const renderer = createRenderer(scenario);
  const ui = createUIBridge();

  const clock = createSimulationClock({
    simHz: scenario.simulation.simHz,
    onTick: (dt, t) => {
      sim.step();

      renderer.syncFromState(sim.state);
      ui.syncFromState(sim.state, sim.logs);

      if (!sim.simStatus()) {
        clock.stop();
        ui.showResults(buildResultsSummary(sim.state, sim.logs));
      }
    },
  });

  return {
    scenario,
    sim,
    clock,
    renderer,
    ui,
  };
}
