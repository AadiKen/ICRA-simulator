# Parametric Hull Specification — Vehicles B and C

**Purpose.** Defines representative hull geometry for Vehicle B (single-screw monohull USV) and Vehicle C (dual-azimuth catamaran USV), sufficient to generate watertight meshes for Capytaine and to populate vehicle configs.

**Design rationale (state this in the paper).** These are *analytic parametric hulls*, not scans or CAD of a physical vessel. Every surface point is defined by a closed-form equation with published parameters, so the geometry is fully reproducible from this document alone and carries no licensing encumbrance. The claim they support is that `coupled6` operates on representative USV-scale geometry with documented provenance — not that they replicate any specific vessel. Swapping in a real hull later requires only regenerating the mesh; no coefficient or code changes.

---

## 1. Hull surface definition

Both hulls use a **generalised Wigley form**. The half-breadth at longitudinal station `x` and depth `z` is:

```
y(x, z) = (B/2) · (1 − (2x/L)²)^a · (1 − (z/T)²)^b
```

with

- `x ∈ [−L/2, +L/2]`, measured from midship, positive forward
- `z ∈ [−T, 0]`, measured from the design waterline, positive up
- `y` is the half-breadth (mirror about `y = 0` for the full hull)
- `a` controls waterline fullness; `b` controls sectional fullness
- `a = b = 1` recovers the classical Wigley hull (Cb = 4/9)

The hull is closed by:
- the flat waterplane at `z = 0`
- a keel line at `z = −T` where `y → 0`
- pointed ends at `x = ±L/2` where `y → 0`

This form is watertight by construction, has no discontinuities, and requires no fairing.

**Frame convention (must match the existing `coupled6` convention):** origin at midship on the centreline at the design waterline, `x` positive forward, `y` positive to starboard, `z` positive up. Note this is the same midship-fixed origin used by the KVLCC2 MMG configs and the wPCC v4 dataset — reuse that path.

**Note on BM_T.** The catamaran transverse metacentric radius is dominated by the separation term:

```
BM_T = (2·I_T,demihull + 2·A_wp,demihull·(s/2)²) / ∇_total
```

The parallel-axis contribution accounts for roughly 98% of BM_T. The very large GM_T and correspondingly short roll period are physically correct for a catamaran and should not be treated as an error.

## 4. Mesh generation requirements

For Capytaine:

- Generate panels on the **wetted surface only** (`z ≤ 0`) plus the waterplane lid if the solver requires it.
- Panel the surface in `(x, z)` parameter space, mapping through the analytic `y(x, z)`. Avoid uniform Cartesian panelling near the pointed ends where `y → 0`, which produces degenerate panels.
- Cluster panels toward the ends and toward the keel where curvature is highest.
- For Vehicle C, generate one demihull and mirror; **do not** exploit port/starboard symmetry in the BEM solve, because the azimuth thrusters break symmetry in operation.
- Verify the mesh is watertight and correctly oriented (outward normals) before solving.

**Required mesh convergence study.** Solve at a minimum of four panel densities (suggest ~800, 1600, 3200, 6400 panels per hull) and report added mass and radiation damping convergence at the wave frequencies of interest. Record the chosen density and the residual convergence error.

**Required cross-check.** Capytaine computes hydrostatic stiffness from the mesh, so it produces independent `GM_T` and `GM_L`. Compare against the analytic values in §2.2 and §3.2 using the existing no-overwrite comparison path. Agreement within a few percent validates both the mesh and the analytic derivation. A larger disagreement indicates a mesh defect or a frame convention mismatch — investigate before proceeding, do not overwrite.

## 5. Provenance tagging

Every parameter in this document is `geometry-derived` or `design-assumption`:

- **Principal particulars, exponents, separation** → `design-assumption` (chosen to be representative of research USVs at this scale)
- **Cb, Cwp, ∇, Awp, KB, BM_T, BM_L, GM_T, GM_L** → `geometry-derived` (closed-form from §1, recomputable)
- **KG, radii of gyration** → `design-assumption` (empirical ratios, no measurement)
- **Actuator positions and sizes** → `design-assumption`
- **Aerodynamic areas** → `geometry-derived` (from the projected profile), with the superstructure contribution `design-assumption`

None of these are `measured`. Vehicle B and Vehicle C validation status is unaffected by this specification — representative geometry does not constitute physical validation, and the existing status strings should not change.
